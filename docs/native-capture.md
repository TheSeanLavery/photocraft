# Native collaboration evidence capture (macOS)

`scripts/native_capture.sh` builds a small Swift developer helper using the installed Apple SDK. It is not a PhotoCraft dependency or product UI. No installation, server, microphone, screen permission prompt, screenshot polling, or software video encoder is used. Recording declares brief activity after compilation (`caffeinate -u -t 10`), without unlocking the session. The wrapper prevents display/system idle sleep only while the recording process runs (`caffeinate -d -i`); the sidecar records this. If the display is already asleep, `caffeinate -u -t 10` declares brief activity; it cannot bypass a locked session. `--displays` lists capturable display bounds without capturing pixels.

```sh
scripts/native_capture.sh --preflight
scripts/native_capture.sh --list
scripts/native_capture.sh /tmp/photocraft-two-clients.mp4 123,456 20 30
scripts/native_capture.sh --inspect /tmp/photocraft-two-clients.mp4 /tmp/photocraft-two-clients-review
```

Use only synthetic test documents. Arrange two or four native PhotoCraft windows side by side on one display, with all their bounds inside the display. Choose their window IDs explicitly from `--list`. The recorder rejects other applications, duplicate or missing IDs, more than four windows, existing output files, invalid duration/frame rate and oversized bounds. It includes only the selected windows; desktop, other applications, menu bar, audio and hardware cursor are excluded. PhotoCraft's drawn participant cursors remain visible. Keep selected windows in place during recording. Coordinates and output dimensions are display points; output is deliberately bounded at that resolution rather than doubling Retina pixels.

ScreenCaptureKit performs capture and pixel conversion. Its queue is bounded to eight frames. AVAssetWriter disables frame reordering and uses the H.264 Baseline profile to avoid retaining ScreenCaptureKit IOSurface buffers for encoder lookahead. It encodes H.264 with VideoToolbox's **require hardware encoder** setting, so inability to obtain a hardware encoder fails rather than silently taking a software path. Encoder backpressure drops samples instead of building an unbounded memory queue. Real capture sample timestamps are retained; static periods may produce fewer samples than the requested maximum FPS. To retain a trailing static interval, the recorder appends one duplicate of the last captured image at the measured monotonic stop time and reports `heldEndFrame`; this is not counted as a new captured sample. Do not derive app frame rate from encoded sample count.

The `.mp4.json` sidecar records window IDs, dimensions, requested frame rate, accepted samples, writer-backpressure drops, sample duration, video duration, wall duration, start UTC, queue depth and required encoder. It also reports callback/status/invalid-frame counts and the explicit held endpoint. It does not claim to count ScreenCaptureKit/internal OS drops. `--inspect` extracts only eight frames after recording through AVFoundation; these review PNGs are not part of the live recording path. Inspect them, and present their absolute paths inline in the parent chat.

`--preflight` does not prompt. If it reports missing Screen Recording permission, stop: the user must authorize the invoking terminal/helper under System Settings → Privacy & Security → Screen & System Audio Recording. Do not request access programmatically or claim a live capture was made. No fallback of simulated/offscreen content is labeled live.

Apple references: [ScreenCaptureKit content filters](https://developer.apple.com/documentation/screencapturekit/sccontentfilter), [Capturing screen content](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos), [VideoToolbox hardware encoder requirement](https://developer.apple.com/documentation/videotoolbox/kvtvideoencoderspecification_requirehardwareacceleratedvideoencoder).

Runtime validation: a ten-second four-native-window moving-cursor probe delivered 275 complete capture frames spanning 10.125 seconds, with no invalid frames or writer backpressure drops. The earlier queue-depth-three/reordering configuration stalled after exactly four frames; those earlier recordings are not motion evidence. Queue depth eight stays at Apple’s documented maximum. This confirms this capture configuration on the tested Mac, not application FPS or drawing latency.

Record one video at a time. The wrapper atomically creates a shared `recording.lock` directory before compiling or recording. A concurrent recording exits with code 75 and reports the owning wrapper PID; it never deletes an existing or apparently stale lock. Normal exit, validation failures, and handled interruption release only the invocation’s own lock. On interruption the wrapper stops and waits for its own recorder before releasing the lock. An uncatchable kill or power loss can leave a lock; verify both recorded PIDs and remove it manually only after confirming no capture remains active. Run `--inspect` after all recording has finished, rather than decoding while another encoder session is active. The sleep assertion watches the recorder PID and ends with that process.
