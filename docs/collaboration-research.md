# Collaboration synchronization research

Reviewed 2026-10-09. These are primary research and protocol specifications.

* [COLiER: Collaborative Editing of Raster Images](https://arxiv.org/abs/2107.05962), Bath et al., 2021: maintains a server document model and synchronizes clients. Its user studies establish communication and synchronization as key requirements. PhotoCraft adopts host authority and a shared document, with a native deterministic brush renderer instead of WebGL.
* [CERVI: collaborative editing of raster and vector images](https://d-nb.info/126544174X/34): collaborative raster/vector editing and synchronization. It informs separating document modifications from private editing state. This does not establish that generic text OT or CRDTs commute with raster blend modes.
* [RFC 8831: WebRTC Data Channels](https://www.rfc-editor.org/rfc/rfc8831): SCTP over DTLS over ICE/UDP supplies integrity, confidentiality and NAT traversal. Reliable ordered edits carry immutable resolved brushes and sequenced stylus samples; lossy unordered presence carries cursors. Keep packets small to avoid head-of-line delays; a stroke chunk caps at 256 samples.

Implementation decisions: host supplies the canonical order; jitter seed, resolved sampled tips/textures, pressure, tilt, rotation, wheel and timestamps travel with the stroke. Selection coverage belongs to the stroke author. Renderer maintains cached sparse coverage across chunks and never sends routine pixel updates. Original COW tiles and a per-author visibility journal permit undoing an old stroke without undoing other artists' newer work. Disjoint strokes composite only newly dirty sparse tiles against their captured COW pre-stroke surface. Overlapping strokes and undo rebuild only the affected layer in canonical begin order, preserving noncommutative blend semantics. Initial document bootstrap may include pixels because existing artwork cannot be reconstructed from new input alone. Reconnection installs a current-document checkpoint with the complete bounded author journal.

The extended protocol journals compiled document commands as well as strokes. A deterministic command carries the author's resolved tools, colors, selection and targets, then executes in an isolated host session. Resource-dependent commands resolve on the initiating artist before admission and carry a typed native-format metadata/tile/blob delta; peers never execute another artist's file paths or scripts. Routine brush streams still send inputs. Reliable CBOR transports native byte resources without numeric JSON arrays. A three-way native-sample merge preserves unrelated same-tile edits when an admitted resource outcome rebases.

Undo and redo operate on each author's mixed journal. Deterministic filters and transforms rerun in order when an earlier author edit is removed. Undoing layer creation retains an empty structural prerequisite when another artist's visible edit depends on that layer. A journal checkpoint retains the original room document, authored command and stroke entries, visibility tombstones, redo stacks, and original chunks for in-flight strokes; reconnect therefore preserves author history instead of treating a current image as its own editable history. Artist selections, Quick Mask, tools, channel targets, clipboard and local tabs remain private. Shared visibility is canonical independently of a viewer's personal layer visibility.

Remaining performance work: affected tile indexes should further restrict overlap and undo recomposition of unrelated same-layer strokes; generic command prediction and host execution currently duplicate heavy work. A complete dependent document rebuild is used when edits cannot commute safely. Host-loss migration and cross-version renderer compatibility remain separate contracts. The protocol validates finite input, authentication identity, nonces, chunk ownership and ordering, resource budgets, and bounded history; invalid or failed engine operations do not advance the authoritative revision. Reliable transfers and checkpoint history also have explicit size limits.

Checkpoint installation builds the archived command journal and pressure-sampled stroke renderers directly, validates sequence metadata, then rebuilds the canonical document once. It does not route archived chunks through live dispatch or generate intermediate network deltas. This removes the former quadratic mixed-history replay cost while preserving in-flight sequence state, author undo floors and structural prerequisites used by peers. A regression covers a hidden creator's layer with 100 peer strokes of two chunks each, followed by checkpoint import and creator redo/undo.
Completed historical stroke authors release their sequencing metadata during import; unfinished owners retain it, so a room can admit successive generations of artists without making its checkpoint unjoinable at the 64-active-member limit. Stroke identity deduplication remains independent of this metadata reclamation. Undo floors are bounded by the 4096-edit archive rather than current membership.
