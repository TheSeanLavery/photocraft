# PhotoCraft Cloudflare hosting

The online editor is https://photocraft-web.theseanlavery.workers.dev/. A Rust Worker streams its generated HTML/JS and 26.8 MiB WASM from the private `photocraft-web-assets` R2 bucket. This avoids the 25 MiB static-asset upload limit without removing editor features. HTML revalidates and hashed assets cache immutably. Content types are explicit, including `application/wasm` for streaming compilation. Editor and Worker glue are generated by Trunk/worker-build; there is no handwritten JavaScript or TypeScript.

The stable signaling address remains https://photocraft-mp.theseanlavery.workers.dev. Each room has its own SQLite-backed Rust `PhotoCraftRoom` Durable Object. Membership, hashed passwords, queued SDP and temporary TURN cache survive Worker restarts. SQL read/mutate/write is synchronous; TURN fetch reloads and reauthorizes after yielding, preventing leave/kick from being undone. Native authentication and host-only signaling routing are preserved. Requests and responses are bounded, JSON CORS uses explicit capabilities without cookies, admission/ICE attempts are rate limited, and alarms clean inactive rooms. Rooms allow 64 participants and 128 queued signals per participant, with 1 MiB queued-state and 240 KiB poll-response limits.

Editor hosting and signaling no longer depend on the operator's Mac or Cloudflare Tunnel. Keep the **host editor tab** open during collaboration: it orders edits and transfers artwork over WebRTC. Cloudflare stores signaling, not artwork. Closing the host expires its room after two minutes. Browser microphone capture/playback remains unavailable.

## Deploy

```sh
cargo install worker-build --version 0.8.7 --locked
cargo test
cargo clippy --all-targets -- -D warnings
cargo clippy --target wasm32-unknown-unknown -- -D warnings
wrangler r2 bucket create photocraft-web-assets # once
wrangler secret put TURN_KEY_ID
wrangler secret put TURN_API_TOKEN
wrangler deploy --dry-run
wrangler deploy
```

TURN credentials belong to the room Worker only, stored as secrets and never included in client artifacts or Git. `ROOM_ORIGIN` is unused. Temporary credentials require active authenticated membership, cache for one hour, and expire after 24 hours. Provider success accepts all 2xx responses, including **201 Created**.

Build from the intended main-based checkout, then upload generated assets before updating HTML:

```sh
NO_COLOR=true trunk build --release --config apps/photocraft-web/Trunk.toml
python3 deploy/cloudflare-edge/publish-web.py
```

The frontend config references the room namespace in `photocraft-mp`, so both addresses reach the same rooms. Retain old hashed artifacts for already-open clients. R2 publication is separate from the older Pages ZIP packaging size gate.

## Acceptance

```sh
PHOTOCRAFT_SIGNALING_URL=https://photocraft-mp.theseanlavery.workers.dev cargo test --test live_signaling -- --ignored
```

Live tests verify preflight, password/token checks, queued signals, polling, departure revocation and actual temporary TURN credentials without printing secrets. Also verify public asset MIME types and WASM hash, browser startup, two-client bootstrap/chat, and room survival after redeploy. Chrome is verified; the in-app browser blocked navigation to this workers.dev frontend during acceptance.

## Room panel invite preview

This branch preserves the deployed room-service source from `2109ba5b` and adds same-domain invitations. `/join/<code>` redirects to `/app/?room=<code>`, where the editor joins through the existing public service. `/app/` streams from the separate `room-panel/` R2 namespace, leaving existing root editor assets intact. Build the editor, run `python3 deploy/cloudflare-edge/publish-web.py --prefix room-panel`, then deploy the tested Worker. Passwords and TURN credentials never appear in invitations. Installed desktop packages also register `photocraft://join/<code>`.
